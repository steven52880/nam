## 渠道倍率的计算规则（B1）

**渠道级倍率**（渠道表"上游分组倍率"列、上游渠道售价、厂商参考成本用它），按顺序取第一个有的：
- `manual`：主人手填值（`channel_ext.manual_discount`）。
- `auto`：按上游逐模型价格推算 = 渠道各模型"上游价 ÷ 原厂价"的中位数（现有 `pricing.Derive`）。
- `group`：令牌所在分组在上游的分组倍率（`upstream_group.ratio`，≤ 0 视为没有）。
- `none`：都没有 → 倍率为 `null`，成本、上游渠道售价、单次成本都为 `null`，附原因：未关联上游、未关联令牌、令牌没有分组、上游没有这个分组的价格和倍率。

**模型级倍率**（算这个模型的成本），按顺序：
- `override`：模型级覆盖（`channel_ext.model_discount`）。
- `manual`：渠道手填值。
- `model`：这个模型自己的"上游价 ÷ 原厂价"（按次计费用按次价相除），模型名先找原名再找别名后的名字。
- `channel`：渠道级倍率的 auto / group。
- `none`：算不出 → 这个模型没有成本。

**偏离标记**：模型的 `model` 倍率相对"基准"偏离 > 1% 时标出。基准 = 上游分组倍率（有的话），否则渠道中位数。含义是"上游给这个模型的标价和原厂价不一致"。

**用到的地方全部改成上面的规则**：渠道表、模型明细、`GET /channels/costs`、"模型与价格"页的渠道列表（`api/prices_detail.go`）、统计入库（`stats/pricer.go`）、评级（`stats/rating.go`）、`channels/live.go`、批量创建预览。

**数据**：上游价格和分组倍率仍从 nam 本地缓存读（`upstream_model_price`、`upstream_group`），每次请求一次性加载成索引，不发 HTTP。

**删除**：`pricing.RefreshAuto`、`PricingInputs` 的写库用途、倍率同步任务里的"折扣推算"。倍率同步任务默认间隔 6 小时 → 1 小时。

## 接口约定：渠道（B1 实现，F 使用）

**`GET /channels` 行（`Row`）**：
- 删除 `drift_fields`；`sync_state` 不再有 `drift`。
- `vendor`：由分组推出。
- `discount`：`number | null`，渠道级倍率。
- `discount_source`：`"manual" | "auto" | "group" | "none"`。
- `discount_reason`：`string`，`none` 时说明原因，其它为空。
- `upstream_group_ratio`：`number | null`，令牌所在分组的上游分组倍率。
- `channel_cost`、`unit_cost`：倍率为 `null` 时也为 `null`。

**编辑（`PATCH /channels/drafts` 里每个 change 的 `ext`）**：
- `"discount": 0.35` → 设为手填。
- `"discount_source": "auto"`（不带 `discount`）→ 清掉手填，回到自动。
- `"vendor"` 照旧可提交，效果是换分组。

**`GET /channels/:id/models`**：
- 顶层：`discount`（可空）、`discount_source`、`discount_reason`、`upstream_group_ratio`、`derived_median`。
- 每个模型：保留 `model`、`official`、`price`、`upstream_input`、`derived`、`reason`、`override`、成本字段；
    - `effective`：`number | null`；
    - `effective_source`：`"override" | "manual" | "model" | "channel" | "none"`；
    - `deviation`：相对基准的偏离（可空）；`deviates`：偏离 > 1%。

**删除**：`GET /channels/:id/drift`、`POST /channels/:id/drift/accept`、`POST /channels/:id/drift/overwrite`。接管（adopt）保留，只是不再存快照。

**新增**：`GET /channels/issues`（见上）。

## 接口约定：上游支持情况（B3 实现，F 使用）

- `Upstream` 新增 JSON 列 `sync_parts`，接口里随上游对象返回：
```json
"sync_parts": {
  "balance":      { "state": "ok", "at": 1794990257, "message": "", "count": null },
  "tokens":       { "state": "fail", "at": 1794990257, "message": "HTTP 401 …", "count": null },
  "groups":       { "state": "ok", "at": 1794990257, "message": "", "count": 13 },
  "model_prices": { "state": "empty", "at": 1794990257, "message": "上游没有提供逐模型价格", "count": 0 }
}
```
- `state`：`ok` 成功；`fail` 拉取失败；`unsupported` 该上游类型不支持；`empty` 成功但没有数据（只用于 `model_prices`）。缺少某一项 = 还没同步过。
- 每次 `Sync`（定时任务和手动同步）都更新对应项。`model_prices` 随 `groups` 一起更新。更新用 SQLite `json_set` 原子写，避免余额任务和倍率任务同时写时互相覆盖。

## 接口约定：厂商定价（B2 实现，F 使用）

- `vendor_pricing` 只留：`vendor_id`、`mode`、`markup`、`draft_ratio *float64`（固定模式待写入的倍率）、`updated_at`。删除 `sell_price`、`last_written_*`、`state`、`pending_price`、`reference_cost`。
    - 迁移：旧行固定模式、`state = 'to_write'` 且有 `sell_price` 的，换算成 `draft_ratio` 保留；其余 `draft_ratio = NULL`。
- **固定模式**：目标倍率 = `draft_ratio`，没有草稿时 = NewAPI 当前 `GroupRatio`。售价 = 目标倍率 × 站点汇率 ÷ 美元参考汇率。都没有 → `unset`。
- **跟随模式**：目标售价 = 参考成本 × 加价比例 → 目标倍率；与 NewAPI 当前售价比较：变化 > 保护阈值 → `pending`；否则不同 → `to_write`（变化 < 最小变动时 `small_change: true`，定时任务不写）。NewAPI 里被手改过也按这个规则覆盖回去（以 nam 为准）。
- **状态**：`synced`、`to_write`、`pending`、`no_channel`、`unset`（删除 `drift`）。
- **`GET /vendor-pricing` 的 item**：`vendor_id`、`vendor`、`group`、`order`、`mode`、`markup`、`sell_price`（当前目标售价）、`reference`、`target_price`、`target_ratio`、`newapi_ratio`、`draft_ratio`、`change`（相对 NewAPI 当前售价，可空）、`small_change`、`state`、`revenue_7d`、`cost_7d`、`margin_7d`。删除 `last_written_*`、`pending_price`。
- **`PUT /vendor-pricing/:id`** `{mode?, markup?, sell_price?, group_ratio?, discard_draft?}`：
    - 固定模式下 `sell_price` 换算成 3 位倍率、`group_ratio` 取整 3 位，存为 `draft_ratio`；等于 NewAPI 当前值时清掉草稿。
    - `discard_draft: true` 清掉草稿。改成跟随模式时清掉草稿。
    - 只写 nam，返回 item。
- **`POST /vendor-pricing/preview`、`/apply`**：去掉 `force`；默认写所有 `to_write`；写完固定模式清掉 `draft_ratio`。
- **`POST /vendor-pricing/:id/confirm`**：只对 `pending`，写入当前目标值。
- **删除** `POST /vendor-pricing/:id/adopt`。
- `GET /vendor-pricing` 不再写库（不再"首次接管"）。
- 定时任务摘要：`N 个厂商；写入 x；待确认 y；无可用渠道 z`。

## 前端（F）

- **渠道页**：
    - 删除漂移：同步状态、筛选项、红底高亮、对比弹窗、右键菜单项、接口、类型、布局槽位 `channels.drift`。
    - 上游分组倍率列：显示数值和来源（手填 / 推算 / 分组倍率）；`none` 显示"无法推算"，悬停看原因；输入数字 = 手填；手填时清空输入 = 回到自动。
    - 规则问题：表格上方的提示条，可展开列表，点击定位到渠道。
- **模型明细**：表头显示渠道倍率、来源、上游分组倍率；每行显示生效倍率和来源；`deviates` 的行用醒目颜色标出，悬停说明"上游给这个模型的标价是原厂价的 X 倍，和分组倍率 Y 不一致"。
- **上游抽屉**：新增"支持情况"列表：绿勾 = 成功；红叉 = 失败 / 不支持 / 没有数据，后面写原因和时间；灰色 = 还没同步。
- **厂商定价**：去掉漂移、采纳、以 nam 为准覆盖、上次写入；固定模式编辑后显示"待写入"，可撤销修改；总览告警和导航徽标只数"待确认"，另加渠道规则问题数。
- **批量创建**：倍率留空 = 自动；预览里显示算出的倍率，算不出显示"无法推算"。
