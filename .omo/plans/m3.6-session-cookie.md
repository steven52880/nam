# M3.6 会话凭证（Cookie + sub2api 自动续期）

## 背景

- 多数中转站登录开了 Cloudflare Turnstile，nam 用账号密码登录会报 `Turnstile token is empty`。
- 很多 NewAPI 站也没开放"系统访问令牌"。
- 方案：主人在浏览器里登录（人机验证由人完成），把会话凭证粘贴进 nam。
    - NewAPI / OneHub：粘贴 `session` Cookie + 用户 ID。
    - sub2api：粘贴 access_token + refresh_token，nam 自动续期并写回数据库。
- 不做：自动破解 Turnstile、内置浏览器。

## 已确认的事实（clansty 版源码）

- NewAPI `main.go:170-178`：`cookie.NewStore`，Cookie 名 `session`，`MaxAge 2592000`（30 天），HttpOnly，SameSite Strict。会话整份存在 Cookie 里，服务端不存。
- NewAPI `middleware/auth.go:95`：会话认证仍要求 `New-Api-User` 请求头等于会话里的用户 ID。
- NewAPI `controller/misc.go:80`：`/api/status` 返回 `turnstile_check`。
- sub2api `service/sub2api_auth.go:152-176`：`POST /api/v1/auth/refresh {refresh_token}` → `{access_token, refresh_token, expires_in}`，每次返回新的 refresh_token（旧的作废）。任一令牌为空或 `expires_in<=0` 视为不完整。
- UNVERIFIED：OneHub 的 Cookie 名是否也叫 `session`；sub2api refresh_token 的有效期；sub2api 前端 localStorage 键名。

## 契约：凭证类型与字段

### 常量（`nam/internal/store/models.go`）

- `CredCookie = "cookie"`：NewAPI、OneHub 可用。
- `CredSub2APISession = "sub2api_session"`：只有 sub2api 可用。
- `Upstream` 新增 `CredUpdatedAt int64 \`json:"cred_updated_at"\``：凭证最后修改时间（Unix 秒），API 写入或续期写回时更新。

### Credential JSON（`api.Credential` 与 `upstream.Credential` 字段必须完全一致）

```go
AccessToken  string `json:"access_token,omitempty"`
Username     string `json:"username,omitempty"`
Password     string `json:"password,omitempty"`
Key          string `json:"key,omitempty"`
Cookie       string `json:"cookie,omitempty"`        // 只存 session 的值，不含 "session="
RefreshToken string `json:"refresh_token,omitempty"` // sub2api_session
ExpiresAt    int64  `json:"expires_at,omitempty"`    // sub2api_session：access_token 过期时间，Unix 秒
```

- `api.Credential.empty()` 要把新字段算进去。
- `upstream_routes.go` 的 `siteFromInput` 用的是 `upstream.Credential(*in.Credential)` 直接转换，字段不一致会编译失败。

### 输入校验（`applyUpstreamInput`，以及 `siteFromInput` 走同一套校验）

- `cookie`
    - 上游类型必须是 newapi 或 onehub，否则 400 "会话 Cookie 只能用于 NewAPI / OneHub 上游"。
    - 用 `upstream.NormalizeSessionCookie` 清洗；失败 400，信息用它返回的中文。
    - newapi 类型时 `platform_user_id` 必须 > 0，否则 400 "会话 Cookie 需要填写用户 ID"。
- `sub2api_session`
    - 上游类型必须是 sub2api，否则 400。
    - access_token、refresh_token 都要非空（TrimSpace 后），否则 400。
    - access_token 去掉可选的 `Bearer ` 前缀。
    - `ExpiresAt` 由服务端用 `upstream.JWTExpiry(access_token)` 算出；解析失败时设为 0（视为已过期，第一次使用就续期）。前端传来的 `expires_at` 一律忽略。
- 凭证有变化（`in.Credential != nil`）时写 `CredUpdatedAt = now`。

### API 输出

- `UpstreamView` 新增 `cred_expires_at int64 \`json:"cred_expires_at"\``：
    - `cookie`：`SessionCookieIssuedAt` 解出的签发时间 + 30 天；解不出时用 `CredUpdatedAt + 30 天`；都没有为 0。
    - 其他类型：0。
    - 计算需要解密凭证；解密失败时为 0，不让列表接口报错。
- `ProbeResult` 新增 `login_captcha bool \`json:"login_captcha"\``：newapi/onehub 探测时取 `/api/status` 的 `turnstile_check`。开启时 `evidence` 末尾追加"；登录需要人机验证"。

## 后端实现

### 新文件 `nam/internal/upstream/session_cookie.go`

- `const SessionCookieTTL = 30 * 24 * time.Hour`
- `NormalizeSessionCookie(raw string) (string, error)`
    - TrimSpace；接受三种格式：纯值、`session=值`、整串 Cookie 头 `a=1; session=值; b=2`（按 `;` 拆，取名为 `session` 的那段）。
    - 整串里没有 `session=` 但含 `=` 和 `;` 时报错"没有找到名为 session 的 Cookie"。
    - 结果为空、或含任何 `< 0x21`、`0x7f`、`;`、`,`、`"`、`\` 字符时报错"Cookie 含非法字符"。
- `SessionCookieIssuedAt(v string) (time.Time, bool)`
    - gorilla/securecookie 格式：`base64url(时间戳|base64(数据)|签名)`。先 `base64.URLEncoding` 解码（失败再试 RawURLEncoding），按 `|` 拆，第一段 ParseInt 为 Unix 秒，必须在 2020 年之后且不晚于 now+1 天。
    - 任一步失败返回 false。
- `CookieExpiresAt(c Credential, credUpdatedAt int64) int64`：供 `UpstreamView` 计算（规则见契约）。
- `captchaHint(err error) error`：错误文本含 `turnstile`（不区分大小写）或 `验证码` 时，返回 `fmt.Errorf("%w（该站开启了人机验证，账号密码无法登录，请改用会话 Cookie）", err)`，否则原样返回。
- `AuthErrorText(credType string, err error) string`：`errors.Is(err, ErrAuth)` 时，cookie 返回"会话 Cookie 已失效，请在浏览器重新登录后粘贴：" + 原文；sub2api_session 返回"登录令牌已失效，请重新登录后粘贴：" + 原文；其余返回 `err.Error()`。

### 适配器

- `newapi.go`
    - `statusData` 新增 `TurnstileCheck bool \`json:"turnstile_check"\``。
    - `ProbeResult` 新增 `LoginCaptcha`（adapter.go），`probeNewAPILike` 填写。
    - `newSession` 新增 `case store.CredCookie`：Cookie 为空或 `userID <= 0` 返回 `ErrAuth`；`c.hdr["Cookie"] = "session=" + v`。不用 cookiejar。
    - `CredPassword` 分支的登录失败错误经 `captchaHint` 包装（保留 `%w ErrAuth`）。
- `onehub.go` 的 `ohSession`：同样新增 cookie 分支（不需要用户 ID，有就照现有逻辑处理）；登录失败经 `captchaHint`。
- `sub2api.go` 的 `s2Open`：新增 `case store.CredSub2APISession`，调用 `s2EnsureAccess` 得到 access_token 后设 `Authorization: Bearer ...`。
- 其他适配器不动；遇到新类型走现有 default 分支返回 `ErrUnsupported`。

### 凭证写回接口（`adapter.go`、`site.go`）

```go
// CredStore persists a rotated credential. Nil means read-only (draft tests).
type CredStore interface {
    Load(ctx context.Context) (Credential, error)
    Save(ctx context.Context, c Credential) error
}
```

- `Site` 新增字段 `Creds CredStore`。
- `site.go` 新增 `dbCredStore{st *store.Store, box *crypto.Box, id uint}`：
    - `Load`：重新 `GetUpstream`，解密并反序列化。
    - `Save`：JSON → `box.Seal` → `UPDATE upstreams SET cred=?, cred_updated_at=? WHERE id=?`。
- `NewCredStore(st, box, id) CredStore`。
- 挂载位置：`Syncer.load`；`api.testUpstream`（已保存上游）；api 层其它用已保存上游构造 Site 的地方（例如 fetch models、createRemoteToken，如果它们自己调 `SiteFor`）。`testDraftUpstream` 不挂。

### 新文件 `nam/internal/upstream/sub2api_session.go`

- `JWTExpiry(tok string) (int64, bool)`：取第二段，RawURLEncoding 解码（兼容带 padding），读 `exp`（数字）。
- `var s2Locks sync.Map // uint -> *sync.Mutex`
- `const s2RefreshSkew = 2 * time.Minute`
- `s2EnsureAccess(ctx, s Site) (string, error)`
    - access_token 为空且 refresh_token 为空 → `ErrAuth`。
    - `ExpiresAt > now + skew` → 直接返回 access_token。
    - `s.Creds == nil` → `fmt.Errorf("登录令牌已过期，保存上游后会自动续期: %w", ErrAuth)`。
    - 加锁（按 `s.ID`）；`Creds.Load` 重新读取；读到的仍未快过期 → 直接用新读到的。
    - 否则 `s2Refresh`；成功后先 `Creds.Save`，Save 失败返回错误；成功返回新 access_token。
    - 锁内不要调用会再次进入 `s2EnsureAccess` 的函数。
- `s2Refresh(ctx, s Site, refresh string) (Credential, error)`
    - `POST /api/v1/auth/refresh`，复用 `s2Session.call`（无 Authorization 头）。
    - 结果不完整（任一令牌为空或 `expires_in<=0`）报错。
    - `call` 返回 ErrAuth，或 apiError（sub2api 对失效 refresh_token 返回非 0 code）都包装成 `fmt.Errorf("续期失败：%s: %w", msg, ErrAuth)`。
    - 新凭证：保留原 Credential 其他字段，替换 AccessToken、RefreshToken，`ExpiresAt = now + expires_in`。
    - 只用 slog 记 `"nam: sub2api token refreshed", "upstream", s.ID`，不打印令牌。

### 同步失败文案

- `Syncer.record` 增加参数或在调用前转换：失败信息用 `AuthErrorText(u.CredType, err)`。尽量少改：给 `record` 加一个 `credType string` 参数，所有调用点传 `u.CredType`（load 失败时传 ""）。

### 安全

- 新字段都在加密的 Cred 里，不出现在 `UpstreamView`。
- 确认 `doJSON`、`callEnvelope`、审计日志都不记录请求头；如果有记录，要把 `Cookie`、`Authorization` 打码。

- `newapi_test.go`：cookie 凭证请求头里有 `Cookie: session=abc` 和 `New-Api-User`；用户 ID 为 0 报 ErrAuth；登录返回 "Turnstile token is empty" 时错误含中文提示且仍 `errors.Is(err, ErrAuth)`；探测时 `turnstile_check:true` → `LoginCaptcha`。
- `onehub_test.go`：cookie 分支。
- `sub2api_session_test.go`：未过期不续期；快过期续期一次并写回内存 CredStore（新 refresh_token）；两个 goroutine 同时调用只请求一次 `/auth/refresh`；refresh 返回 401/非 0 code → ErrAuth；`Creds==nil` 且过期 → ErrAuth 且不请求 refresh；`JWTExpiry`。
- api 层：cookie 缺用户 ID 400；cookie 用于 sub2api 400；sub2api_session 缺 refresh_token 400；`cred_updated_at` 更新；`cred_expires_at` 输出。

## 前端实现

- `web/src/api/types.ts`
    - `CredType` 加 `'cookie' | 'sub2api_session'`。
    - `Credential` 加 `cookie?`、`refresh_token?`。
    - `Upstream` 加 `cred_updated_at: number`、`cred_expires_at: number`。
    - `ProbeResult` 加 `login_captcha?: boolean`（找到 ProbeResult 的定义处）。
- `pages/upstreams/constants.ts`：标签
    - `cookie` → "会话 Cookie + 用户 ID"
    - `sub2api_session` → "登录令牌（自动续期）"
    - 可选凭证按上游类型过滤：newapi/onehub 加 cookie；sub2api 加 sub2api_session（排在 access_token 前面并作为默认）。
- `UpstreamForm.tsx`
    - cookie：多行 Textarea（`font-mono`，`autoComplete="off"`，`spellCheck=false`）+ 用户 ID 输入框（onehub 时可选）+ 可折叠说明：
        - 在浏览器登录上游站，按 F12 → 应用（Application）→ Cookie → 复制 `session` 的值；
        - 用户 ID：控制台运行 `JSON.parse(localStorage.getItem('user')).id`（带复制按钮）；
        - 提示"Cookie 约 30 天过期，在网页上退出登录不会让它失效"。
    - sub2api_session：两个密码框 access_token、refresh_token + 可折叠说明：
        - 控制台运行一行代码，遍历 localStorage，打印所有键名含 `token` 的项（键名未确认，用遍历方式）：
          `Object.keys(localStorage).filter(k=>/token/i.test(k)).forEach(k=>console.log(k, localStorage.getItem(k)))`
        - 提示"nam 会自动续期，请不要在别处同时使用这对令牌"。
- `wizard/state.ts`：校验与提交
    - cookie：cookie 非空；newapi 时用户 ID 必须是数字；提交 `platform_user_id`。
    - sub2api_session：两个令牌都非空。
- 探测步骤：`login_captcha` 为 true 时，默认凭证类型改为 cookie，显示提示条"该站登录需要人机验证，账号密码无法使用，请用会话 Cookie"；用户仍选 password 时显示黄色警告。
- `tabs/CredentialDialogs.tsx`：支持两种新类型（复用 UpstreamForm 的凭证部分）。
- 概览页 / 上游列表：
    - cookie 且 `cred_expires_at > 0`：显示"Cookie 约 N 天后过期"；≤3 天黄色，已过期红色。
    - sub2api_session：显示"凭证更新于 x 前"（用 `cred_updated_at`）。
    - `last_sync_error` 含"已失效"时显示红色和"更换凭证"按钮。
- 文案全部中文；不用 `as any` / ts-ignore；`npm run build` 通过。
