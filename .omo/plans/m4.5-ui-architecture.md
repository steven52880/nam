## 分层与目录

### 分层规则

- **从低到高共七层，只能引用同层或更低层**
    - **L1 `lib/`**：纯工具和通用 hook。不引用 `components/`、`pages/`、`hooks/`；对 `api/` 只允许 `import type`（只能来自 `@/api/types*`）。
    - **L2 `api/`**：请求、类型、查询键、共享查询、失效规则。
    - **L3 `hooks/`**：跨页面的 hook（`useActionMutation`、`useSession`、`useTheme`）。
    - **L4 `components/ui/`**：基础组件（Radix 封装、Combobox、Banner、Section）。不取数据；对 `api/` 只允许 `import type`。
    - **L5 通用组合组件**：`components/{table,cells,form,wizard,filters,dnd}`，以及根目录的 `components/ConfirmDialog.tsx`、`ChipEditor.tsx`、`PriceText.tsx`。不取数据；对 `api/` 只允许 `import type`。
    - **L6 业务组件**：`components/{pickers,entities,model-picker}`。可以取数据，但只能通过 `api/queries.ts` 和 `hooks/useActionMutation.ts`。
    - **L7 外壳和页面**：`components/layout/`、`pages/`、`app/`。可以引用以上全部。
- **页面之间不能互相引用**  
  两个以上页面要用的东西，放到 `components/entities/`（业务组件）、`lib/`（纯工具）或 `api/`（数据）。`app/` 引用 `pages/` 是路由注册，允许。
- **现有违规和处理批次**
    - 第一批：`Sidebar.tsx:6`、`TopBar.tsx:18`、`VendorSection.tsx:16` 引用 `pages/channels/useChannels` → 改用 `api/queries.ts` 的 `useChannels()` 和 `keys.channels`。
    - 第一批：`Sidebar.tsx:7` 引用 `pages/pricing/usePrices` → `usePriceCounts()` 移到 `api/queries.ts`。
    - 第一批：`ApplyDialog.tsx:10` 引用的 `showValue`（`DriftDialog.tsx:24`）→ 移到 `lib/format.ts`，同名同输出。
    - 第一批：`AddTokenDialog.tsx:10`、`UpstreamDrawer.tsx:26` 等引用的 `Field`（`UpstreamForm.tsx:37-45`）→ <u>原样</u>移到 `components/form/Field.tsx`，第二批再扩展接口。
    - 第一批：`TopBar.tsx:17` 的 `ApplyDialog` → `components/entities/ApplyDialog.tsx`；`StepTokens.tsx:7` 的 `AddTokenDialog` → `components/entities/AddTokenDialog.tsx`。上面两项完成后再移动，移动后它们不再引用任何 `pages/`。
    - 第一批：`Overview.tsx:11` 引用 `pages/audit/AuditBadges` → `AuditBadges.tsx` 移到 `components/entities/`，第二批改用 `StatusBadge`。
- **逻辑和组件分开**  
  能写成纯函数的逻辑（排序、分组、对账、视图模型、格式化、剪贴板、网址参数）放在单独的 `.ts` 文件，组件只负责组装。纯函数都要写单元测试，见"测试"。

### 架构检查脚本

- **`web/scripts/check.mjs`**：`npm run build` 的第一步，也可以单独运行 `npm run check`。只用 Node 自带模块，逐文件按规则检查；跳过 `*.test.ts`。
- **引用路径规范化**：`@/x` 和相对路径（`./`、`../`）都先换算成相对 `src/` 的路径再判断层级；`import type` 和普通 `import` 分开识别。
- **规则**：每条规则带"从第几批开始生效"的标记，那一批收尾时打开
    - **第一批**
        - `[数字px]`、`数字px` 字面量（`1px` 除外）。
        - 分层：按"分层规则"判断每个 import；`pages/a/**` 不能引用 `pages/b/**`；L1–L5 只能 `import type` 来自 `@/api/types*`。
        - `useQuery(`、`useQueries(` 只能出现在 `api/queries.ts`。
        - 手写的查询键数组 `queryKey: [` 只能出现在 `api/keys.ts`；其它地方的 `queryKey:` 必须来自 `keys.xxx()`（失效、`cancelQueries`、`setQueryData`、登录退出清理都可以用）。
        - `useMutation(`、`toast.error(errorText` 只能出现在 `hooks/useActionMutation.ts`。
    - **第二批**：`function Field`、`function Line`、`function Section` 只能出现在 `form/Field.tsx`、`ui/section.tsx`；`bg-destructive/10`、`bg-warning/15` 只能出现在 `ui/banner.tsx`；`pages/`、`components/entities/` 下的 `DialogContent` 不能带 `max-w-`；`useSearchParams(` 只能出现在 `lib/url-state.ts`。
    - **第三批**：不能引用 `components/data-grid`、`RowContextMenu`。
    - **第四批**：`<table` 只能出现在 `components/table/`；不能有 `<datalist`；`@/components/ui/select` 只能在白名单文件里使用（固定选项：`ChannelToolbar.tsx` 的分组方式和统计时长、`UpstreamForm.tsx` 的类型和凭证、`VendorSection.tsx` 的渠道类型、`Stats.tsx` 的维度、`IntervalRow.tsx` 的时间单位）。
- **输出**：`文件:行号 规则名 说明`，有违规就以退出码 1 结束。
- **例外**：行尾写 `// check-ignore: 规则名 原因` 可以跳过一行，汇报时必须列出全部例外。

## 基础模块

### 尺寸 `lib/size.ts`

```ts
/** 根字号（像素）。第一次调用时读取并缓存。 */
export function rootPx(): number;
export function remToPx(rem: number): number;
export function pxToRem(px: number): number;
/** 保存列宽时取到 0.25rem，避免浮点噪声导致"未保存"误报。 */
export function roundRem(rem: number): number;
```

- **样式**：`tailwind.config.ts` 的字号和圆角改 rem，`index.css` 设 `html { font-size: 110% }`。字号：xs 0.6875rem / 1rem，sm 0.75rem / 1rem，base 0.8125rem / 1.25rem，lg 0.9375rem / 1.375rem，xl 1.125rem / 1.625rem，2xl 1.375rem / 1.875rem。
- **代码里的尺寸**：一律以 rem 为单位写数字，使用时调用 `remToPx()`。
- **例外**：拖动启动阈值（4 像素）这类"鼠标移动距离"不是界面尺寸，保留像素，用 `// check-ignore` 标注。
- **现有列宽换算**：像素 ÷ 16，取到 0.25rem（例如 220 → 13.75，90 → 5.75）。

### 失效规则 `api/invalidate.ts`

- **"改了什么 → 刷新什么"只写在这里**，提交成功后调用对应函数，页面不自己拼失效列表。

| 改动 | 刷新 |
|---|---|
| 上游（新增、编辑、删除、同步、换凭证、改汇率） | `upstreams.all`、`channels.all` |
| 令牌（新增、删除、改模型） | `upstreams.tokens(id)`、`upstreams.list`、`channels.all` |
| 厂商（增删改、排序） | `vendors.all`（含厂商匹配）、`channels.all`、`prices.all` |
| 渠道草稿、应用、漂移处理、接管 | `channels.all`（含计划和漂移详情）、`stats.channels` 前缀 |
| 缓存测试开始、结束、取消 | `channels.latestCacheTests` |
| 价格覆盖、别名、模型级折扣、缓存覆盖 | `prices.all`、`channels.all` |
| 设置保存（含调度间隔） | `settings`、`jobs` |
| 手动触发任务 | `jobs` |

### 提交助手 `hooks/useActionMutation.ts`

```ts
export function useActionMutation<TVars = void, TData = unknown>(opts: {
  mutationFn: (vars: TVars) => Promise<TData>;
  /** 成功提示；不传则不提示。 */
  success?: string | ((data: TData, vars: TVars) => string);
  /** 成功后的刷新，通常是 invalidate.xxx。 */
  invalidate?: (qc: QueryClient, data: TData, vars: TVars) => Promise<void> | void;
  onMutate?: (vars: TVars) => void;
  onSuccess?: (data: TData, vars: TVars) => void;
  /** 返回 true 表示已自行处理，不再弹默认的错误提示。 */
  onError?: (err: Error, vars: TVars) => boolean | void;
  onSettled?: () => void;
}): UseMutationResult<TData, Error, TVars>;
```

- 执行顺序：`invalidate` → `success` 提示 → `onSuccess`。
- 默认错误提示固定为 `toast.error(errorText(e))`。需要内联显示错误的地方（例如 `ApplyDialog` 的问题列表、`useChannelActions` 改上游失败后也要刷新）用 `onError` 自行处理。

### 网址参数 `lib/url-state.ts`

```ts
/** 纯函数：在 prev 的基础上应用修改，null 表示删除，其余参数保持不变。 */

  get: (key: string) => string | null;
```

### 布局仓库 `lib/layout/`

- **为什么不用普通 Context**：拖动列宽时每秒会改几十次状态，放在 Context 里会让整个应用跟着重新渲染。所以仓库放在 React 外面，组件按槽位订阅；<u>高频变化只留在组件自己的状态里</u>，松开鼠标时才写一次仓库。
- **仓库接口**（不依赖 React，单独测试）

```ts
export type LayoutStatus = 'loading' | 'ready' | 'error';
export interface LayoutDoc { v: 1; slots: Record<string, { v: number; data: unknown }> }
export interface SlotSpec<T> {
  id: LayoutSlotId;
  version: number;
  defaults: () => T;
  /** 校验 data；不合法返回 null，改用默认值。 */
  parse: (data: unknown) => T | null;
}
export interface LayoutStore {
  status(): LayoutStatus;
  get<T>(spec: SlotSpec<T>): T;               // 同一份数据返回同一个引用
  set<T>(spec: SlotSpec<T>, value: T): void;  // status 不是 ready 时忽略
  reset(id: LayoutSlotId): void;              // status 不是 ready 时忽略
  /** 任何变化都通知；槽位没变时 get 返回同一个引用，useSyncExternalStore 不会重新渲染。 */
  subscribe(cb: () => void): () => void;
  isDirty(): boolean;
  loaded(doc: LayoutDoc | null): void;        // 加载成功：已保存 = 当前 = doc，status = ready
  failed(): void;                             // 加载失败：status = error
  snapshot(): LayoutDoc;                      // 当前布局，含没访问过的槽位
  markSaved(doc: LayoutDoc): void;            // 已保存 = doc，当前不变
  revertToSaved(): void;
  resetAll(): void;
}
export function createLayoutStore(): LayoutStore;
```

- **数据保留规则**
    - "当前"初始化为"已保存"的完整拷贝（原始数据，不解析）；没访问过的槽位、不认识的槽位原样保留在 `snapshot()` 里。
    - `get` 只解析不写回；版本不符或 `parse` 返回 null 时返回默认值，但<u>不改原始数据</u>。
    - 对账（如表格列的增删）只在读取时计算，<u>挂载时不写回、不产生"未保存"</u>；用户操作后 `set` 写入的才是对账后的值。
    - 文档版本 `doc.v` 不是 1 时：当作空文档加载（全部默认），`console.warn`；保存时写成第 1 版。
    - `reset(id)` 删除该槽位的当前值；`resetAll()` 清空全部当前值（不认识的槽位也清空）。
- **判断是否改动**：按槽位比较 `stableStringify(当前)` 和 `stableStringify(已保存)`，结果缓存，只在 `set / reset / loaded / markSaved / revert / resetAll` 后重算。
- **`LayoutProvider` 的生命周期**（`AppShell` 里使用，`<LayoutProvider key={userId} load={api.uiLayout} save={api.saveUiLayout}>`）
    - **唯一的加载入口**：挂载时调用 `load()`，不经过 TanStack Query。`key={userId}` 保证换用户时重建仓库。
    - **过期响应**：每次加载带一个递增的代次，组件卸载或重试后，旧代次的响应直接丢弃。
    - **加载完成前**：表格照常显示（用默认布局），但<u>改列宽、拖动、显示 / 隐藏列、拖动分组、拖动下栏都不可用</u>（手柄隐藏，菜单项禁用并提示"布局加载中"）；保存按钮禁用。
    - **加载失败**：`status = error`，顶栏按钮显示"布局加载失败，点击重试"；布局编辑仍不可用，直到重试成功。
    - **保存**：点击时取 `snapshot()` 固定下来，发出请求，`saving = true`，期间保存按钮禁用（<u>不允许并发保存</u>），用户可以继续调整布局。成功后只调用 `markSaved(那份快照)`，所以保存期间的新调整仍然显示为"未保存"。失败时提示错误，状态不变。
- **React hook**
    - `useLayoutSlot(spec)` → `[value, set, reset]`，`useSyncExternalStore(store.subscribe, () => store.get(spec))`；其它槽位变化时引用不变，不会重新渲染。
    - `useLayoutEditable()` → `boolean`（`status === 'ready'`），表格和分栏用它决定是否允许调整。
    - `useLayoutControls()` → `{ status, dirty, saving, save, retry, revertToSaved, resetAll }`，给顶栏按钮用。

- **对账** `layout.ts`
    - `reconcileOrder(saved, currentIds, defaultIds)`：保留 `saved` 中仍存在的 id；新列插在它在默认顺序里的前一列后面，找不到前一列时放在最前。`fixed` 列不在 `order` 里，渲染时保持在默认位置（勾选列、拖动手柄列在最左，操作列在最右）。
    - `reconcileWidths(saved, columns)`：rem 转像素，限制在最小列宽到 60rem；没保存的列使用默认宽度。
    - `diffVisibility(current, columns)`：只返回与默认不同的项；`fixed` 列永远可见。
- **写回时机**：拖完列宽、拖完列顺序、改可见性、改排序、自动调整后，各写一次槽位。
- **排序** `sorting.ts`
    - `sortRows(rows, specs, columns)`：稳定排序（相等时保持原顺序）；按 `specs` 依次比较；访问函数返回 `null`、`undefined`、`''`、`NaN` 视为空值，<u>空值不论升序降序都排在最后</u>，并且两行都为空时继续比较下一个排序键。
    - 文字用 `Intl.Collator('zh-CN', { numeric: true })`；数字按数值比较。
    - 不用 TanStack 的 `sortUndefined`：8.21.3 在两边都为空时直接返回 1，会跳过后面的排序键（审查已实测）。
    - `nextSort(userSort, columnId)`：只看<u>用户排序</u>，不看实际生效的排序：`null 或其它列 → {id, asc}`；`{id, asc} → {id, desc}`；`{id, desc} → null`（回到默认排序）。这样即使默认排序里已经有"优先级降序"，点击优先级也会先变成升序。
- **列宽与自动调整**
    - `<table style={{ width: 各列宽度之和 }}>` + `<colgroup>`，`table-layout: fixed`；表头 `sticky top-0`；超出时容器横向滚动。
    - 每个单元格的内容包在 `<div data-cell-content class="truncate">` 里，表头内容包在 `<div data-header-content>` 里。
    - `BodyRows` 用 `memo`，props 里不包含列宽；拖动列宽时只有表头和 `<colgroup>` 重新渲染。
    - **改宽手柄**：用 TanStack 的 `header.getResizeHandler()`（同时绑定 `onMouseDown` 和 `onTouchStart`）；手柄上的 `pointerdown / mousedown / touchstart / click` 都阻止冒泡，不触发拖动换列和排序；`onDoubleClick` 调用自动调整并阻止冒泡。拖动过程中只改组件状态，结束（`columnSizingInfo.isResizingColumn` 从有变无）时写回槽位。
    - **自动调整** `autoFit(container, columnId, minPx, maxPx)`：在表格容器里临时放一个隐藏的测量层（`position:absolute; visibility:hidden; width:max-content; white-space:nowrap`），把这一列已渲染的 `data-cell-content` 和表头内容逐个 `cloneNode(true)` 放进去，克隆体去掉 `truncate`、宽度设为 `max-content`，取 `getBoundingClientRect().width` 的最大值，加上单元格左右内边距和边框（从计算样式读取），限制在最小列宽到 40rem，最后移除测量层。最多测量 500 个单元格；折叠组里没渲染的行不参与。<u>这样既能变宽也能变窄，重复双击结果不变</u>。
- **拖动**（`useTableDnd`）
    - 整张表只有<u>一个</u> `DndContext`，包在表格外层容器上（不在 `<table>` 里面），`accessibility={{ container: document.body }}`，把辅助元素放到表格外面。
    - 传感器：`PointerSensor`（移动 4 像素才开始）+ `KeyboardSensor`（获得焦点后空格拿起、方向键移动、空格放下、Esc 取消）。
    - 三种拖动对象用 `data.type` 区分：`column`（表头，横向，`restrictToHorizontalAxis`）、`group`（组标题行，纵向）、`row`（数据行，纵向，`onRowReorder` 时）。
    - 拖动影子用 `DragOverlay`，通过 portal 放到 `document.body`。
    - 拖动结束后的那一次 `click` 不触发排序或行点击（用一个"刚拖完"标记，下一帧清除）。
    - Esc 取消时不改变任何顺序。
    - **拖动分组**：开始时 `collapseAll = true`，`measuring` 使用 `MeasuringStrategy.Always`（行数会变化）；结束或取消时恢复；顺序变化时才调用 `onGroupReorder(可见组的新顺序)`。
    - `useLayoutEditable()` 为 false 时，列和分组的拖动、改宽都禁用；`rowReorderDisabled` 只禁用拖动行。
- **分组**
    - 展开状态存成"已展开的组"集合，默认为空，即<u>全部折叠</u>；新出现的组自然也是折叠的。
    - `groupResetKey` 变化时清空集合；`expandAll` 为 true 时视为全部展开（集合不变，取消后恢复）。
    - 组键和显示文字分开：`groupBy` 返回键，`groupLabel(key)` 返回显示文字。兜底组的键是空字符串。

- **键盘**：表格容器的 `onKeyDown` 先检查 `containerRef.current.contains(event.target)`，不是来自表格内部 DOM 的事件直接忽略。原因：右键菜单、下拉框是 portal，键盘事件会沿 React 树冒泡到表格，否则方向键会移动表格选区。
- **可见性变化时的清理**：编辑中的单元格所在列被隐藏、所在行被折叠或筛掉时，取消编辑；框选的起点或终点不再可见时，清除选区。

    - 表体一个 `ContextMenu.Root`，`<ContextMenu.Trigger asChild><tbody>…</tbody></ContextMenu.Trigger>`；`onContextMenu` 时从事件目标的 `closest('[data-row-id]')` 找到行并记下，菜单内容渲染 `rowMenu(该行)`；没找到行（如组标题行）就 `preventDefault` 不打开。

- **右侧列对齐**：数值列用固定的 rem 宽度并右对齐，每一项自然上下对齐。不用 CSS 子网格（cmdk 会在列表外包好几层元素）。
